Comparison

Tern vs Rust

Rust gets memory safety from ownership and borrowing. Tern gets it by having no references at all: every value is a copy, so there’s nothing to borrow, and races are still compile errors.

curl -fsSL https://ternlang.dev/install.sh | sh
tern new myapp && cd myapp

What’s different

  • No lifetimes, no borrow checker. Functions change a caller’s variable only through a mut parameter with & at the call site, and arguments can’t overlap.
  • Reference counting with lazy copies instead of ownership. Nothing can form a cycle, so nothing leaks.
  • No async/await. Green-thread tasks; a million spawned and joined in 41 ms against tokio’s 219 ms.
  • Python-shaped syntax, which coding agents get right more often than lifetimes.

Pick Rust when

  • You need crates.io, no_std or embedded targets, Windows, or explicit control over memory layout.
  • You need a stable language today.

Questions

Is Tern as fast as Rust?

On our 10 compute benchmarks it is ahead or tied on all of them. Rust still wins single-threaded WebAssembly binary-trees and uses slightly less memory on native binary-trees.

Is Tern memory safe?

Yes. There are no pointers or references, values are reference counted with copy-on-write, and the compiler rejects data races in parallel code.
