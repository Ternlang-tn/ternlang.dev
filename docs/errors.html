#Compiler errors

This page lists the errors the Tern compiler reports, with what each one means and how to fix it. Search the page for the text of your error: each heading is an error message, with the parts that change (names, types, counts) written in capitals, like NAME, TYPE, or N. Every entry has a short program that produces the error, the exact output of the compiler, and a fixed program. The last section covers runtime errors, which happen while a program runs.

#How to read an error

The compiler checks the whole file before it builds anything. Each problem is one line:

prog.tn:12: error: can't modify parameter `n`: parameters are read-only unless declared `mut`
prog.tn:12: hint: to change only a local copy, copy it first (`n2 = n`) and change `n2`; ...
1 error(s); not compiled.
  • prog.tn:12 is the file and line.
  • error: says what is wrong. Type and safety errors are all reported at once; a syntax error (the file can't be read as Tern at all) stops at the first one.
  • hint: appears when the compiler recognizes a habit from another language or a likely typo, and says what to write instead. Not every error has one.

In the examples below the file name is left out, so 5: error: ... means line 5.

For tools and agents, check --json prints the same information as JSON on stdout:

tern check --json prog.tn
{"ok": false, "errors": [{"file": "prog.tn", "line": 2,
  "message": "can't modify parameter `n`: parameters are read-only unless declared `mut`",
  "hint": "to change only a local copy, ...", "source": "n += 1"}]}

hint is null when there is none, and source is the offending line. A clean file gives {"ok": true, "file": ...}. The --json flag also works with run and build.

#Syntax

Syntax errors come from reading the file, before any types are checked. Only the first one is reported. Many of them come with a hint when the line looks like another language; those are listed in Habits from other languages.

#expected fn, struct, enum, type, const, or extern at the top level

The top level of a file may only hold import, from ... import, struct, enum, const, fn, extern, and export fn. Statements and variables live inside functions. There are no global variables; a value that never changes can be a const.

Does not compile
limit = 5

fn main():
    print(limit)
Compiler output
1: error: expected `fn`, `struct`, `enum`, `type`, `const`, or `extern` at the top level
1: hint: there are no global variables; for a value that never changes, write `const LIMIT = 5` (a variable that changes belongs in a function, or in a struct you pass around)

Make it a constant (or, if it changes, a variable inside a function that you pass around):

const LIMIT = 5

fn main():
    print(LIMIT)
Output
5

#expected TOKEN, found TOKEN

The parser needed a particular token and saw something else. The most common case is a missing : at the end of an if, for, while, fn, struct, or match line.

Does not compile
fn main():
    x = 3
    if x > 0
        print("positive")
Compiler output
3: error: expected `:`, found end of line
fn main():
    x = 3
    if x > 0:
        print("positive")
Output
positive

#expected an indented block, found TOKEN

A line that ends in : must be followed by an indented block (or a single statement on the same line). For an empty block, write pass.

Does not compile
fn main():
    x = 3
    if x > 0:
    print("positive")
Compiler output
4: error: expected an indented block, found 'print'
fn main():
    x = 3
    if x > 0:
        print("positive")
Output
positive

#expected a name, found TOKEN

The parser needed a name (of a variable, function, field, or type) here.

Does not compile
fn main():
    for 1 in [1, 2]:
        pass
Compiler output
2: error: expected a name, found 1
fn main():
    for n in [1, 2]:
        print(n)
Output
1
2

#expected end of line, found TOKEN

The statement was complete, but more text followed on the same line. Put one statement on each line.

Does not compile
fn main():
    print(1) print(2)
Compiler output
2: error: expected end of line, found 'print'
fn main():
    print(1)
    print(2)
Output
1
2

#expected =, found end of line

A variable is created by giving it a value. x: int alone is not a declaration.

Does not compile
fn main():
    count: int
    count = 3
    print(count)
Compiler output
2: error: expected `=`, found end of line
2: hint: a variable needs a value when it is created: `x: int = 0`
fn main():
    count: int = 0
    count = 3
    print(count)
Output
3

#unexpected TOKEN

The parser found a token that can't start or continue an expression here.

Does not compile
fn main():
    total = )
Compiler output
2: error: unexpected ')'
fn main():
    total = 0
    print(total)
Output
0

#unexpected indentation: this line is indented more than the block it is in

A line is indented more than the line before it, but the line before doesn't end in :. Only a block after : may be indented further.

Does not compile
fn main():
    x = 1
        y = 2
    print(x, y)
Compiler output
3: error: unexpected indentation: this line is indented more than the block it is in
fn main():
    x = 1
    y = 2
    print(x, y)
Output
1 2

#this line's indentation doesn't match any enclosing block

When a block ends, the next line must line up with one of the blocks around it. Here line 4 is indented 6 spaces, but the blocks are at 4 and 8. Use 4 spaces per level.

Does not compile
fn main():
    if true:
        x = 1
      print(x)
Compiler output
4: error: this line's indentation doesn't match any enclosing block
fn main():
    x = 0
    if true:
        x = 1
    print(x)
Output
1

#unterminated string

A string has no closing " on the same line. Strings are one line; write \n for a line break.

Does not compile
fn main():
    print("hello)
Compiler output
2: error: unterminated string
fn main():
    print("hello")
    print("two\nlines")
Output
hello
two
lines

#unterminated string inside f-string

This usually means a { in an f-string has no closing }. The compiler keeps reading the expression inside the braces, takes the f-string's closing " as the start of a new string, and reaches the end of the line.

Does not compile
fn main():
    x = 1
    print(f"x = {x")
Compiler output
3: error: unterminated string inside f-string
fn main():
    x = 1
    print(f"x = {x}")
Output
x = 1

#f-string has } without an opening { (write }} for a brace)

In an f-string, { and } mark expressions. For a literal brace, double it.

Does not compile
fn main():
    print(f"a } b")
Compiler output
2: error: f-string has `}` without an opening `{` (write `}}` for a brace)
fn main():
    n = 2
    print(f"{{n}} is {n}")
Output
{n} is 2

#can't read TEXT inside the f-string

The text between { and } isn't an expression. The usual cause is a format spec such as {x:.2f}: f-strings have none. Use the fmt module instead.

Does not compile
fn main():
    price = 3.14159
    print(f"{price:.2f}")
Compiler output
3: error: can't read `price:.2f` inside the f-string
3: hint: f-strings have no format specs: `import fmt`, then `{fmt.fixed(x, 2)}` (2 decimals), `fmt.zero_pad(n, 3)`, `fmt.pad_left(s, width, " ")`
import fmt

fn main():
    price = 3.14159
    print(f"{fmt.fixed(price, 2)}")
Output
3.14

#unexpected character 'C'

The character can't appear in Tern code outside a string. Common ones are ;, ', !, $, and @.

Does not compile
fn main():
    x = 5 $ 3
Compiler output
2: error: unexpected character '$'
fn main():
    x = 5 - 3
    print(x)
Output
2

#left side of = must be a variable, field, or element

Only a variable (x), a field (p.x), or an element (xs[i], m[k]) can be assigned to.

Does not compile
fn first() int:
    return 1

fn main():
    first() = 3
Compiler output
5: error: left side of `=` must be a variable, field, or element
fn first() int:
    return 1

fn main():
    x = first()
    x = 3
    print(x)
Output
3

#positional arguments must come before named ones

When building a struct you may give fields by position, by name, or both, but the positional ones come first.

Does not compile
struct Point:
    x, y: int

fn main():
    p = Point(x=1, 2)
Compiler output
5: error: positional arguments must come before named ones
struct Point:
    x, y: int

fn main():
    p = Point(1, y=2)
    print(p)
Output
Point{x: 1, y: 2}

#named arguments are only for building structs

Functions take positional arguments only. name=value works only in a struct or enum variant constructor. print has no end= or sep=; build the line as a string first.

Does not compile
fn area(w: int, h: int) int:
    return w * h

fn main():
    a = area(w=2, h=3)
Compiler output
5: error: named arguments are only for building structs
5: hint: functions take positional arguments only: `f(1, 2)`
fn area(w: int, h: int) int:
    return w * h

fn main():
    a = area(2, 3)
    print(a)
Output
6

#& needs a variable, field, or element

&x passes a place that a mut parameter can change. A literal or a computed value has no place to change.

Does not compile
fn inc(n: mut int):
    n += 1

fn main():
    inc(&5)
Compiler output
5: error: `&` needs a variable, field, or element
fn inc(n: mut int):
    n += 1

fn main():
    x = 5
    inc(&x)
    print(x)
Output
6

#export goes before fn

Only functions can be exported (for C, JavaScript, or Swift callers). Structs and enums can't.

Does not compile
export struct Point:
    x: int

fn main():
    pass
Compiler output
1: error: `export` goes before `fn`
struct Point:
    x: int

export fn origin_x() int:
    return Point(0).x

fn main():
    print(origin_x())
Output
0

#function NAME is defined twice

There is no overloading: each function name in a module is used once. Give the second one another name.

Does not compile
fn show(n: int):
    print(n)

fn show(s: str):
    print(s)

fn main():
    show(1)
Compiler output
4: error: function `show` is defined twice
fn show_int(n: int):
    print(n)

fn show_str(s: str):
    print(s)

fn main():
    show_int(1)
    show_str("a")
Output
1
a

#lambdas are written fn(x) x + 1 (one expression)

#a lambda is one expression with no colon: fn(x) x * 2

A lambda can't hold statements. For more than one line, define a nested fn and pass it by name.

Does not compile
fn main():
    xs = [1, 2, 3]
    ys = xs.map(fn(x):
        return x * 2)
Compiler output
3: error: unexpected ':'
3: hint: a lambda is one expression with no colon: `fn(x) x * 2`; for more lines, define a nested `fn name(...)` and pass `name`
fn main():
    xs = [1, 2, 3]
    fn double(x: int) int:
        y = x * 2
        return y
    print(xs.map(double), xs.map(fn(x) x * 2))
Output
[2, 4, 6] [2, 4, 6]

#there are no comprehensions: xs.map(fn(x) ...) and xs.filter(fn(x) ...)

Does not compile
fn main():
    xs = [1, 2, 3]
    ys = [x * 2 for x in xs]
Compiler output
3: error: expected `,`, found 'for'
3: hint: there are no comprehensions: `xs.map(fn(x) ...)` and `xs.filter(fn(x) ...)`, or a loop with `push`
fn main():

    ys = xs.map(fn(x) x * 2)
    print(ys)
Output
[2, 4, 6]

#Names and types

#unknown variable NAME

The name isn't a variable in scope. Usually it is a typo (the hint suggests a close name), a variable created inside a block and used after it, or a name from another language (True, None, self). A variable lives until the end of the block that created it, so create it before the if or loop if you need it after.

Does not compile
fn main():
    total = 0
    for x in [1, 2, 3]:
        total += x
    print(totl)
Compiler output
5: error: unknown variable `totl`
5: hint: did you mean `total`?
fn main():
    total = 0
    for x in [1, 2, 3]:
        total += x
    print(total)
Output
6

Booleans are lowercase. None exists, as the empty Option, but it needs to know what kind of Option it is:

fn main():

#Mutation, mut, and &

Tern has no references: every value is a copy, and a function can change a caller's variable only through a mut parameter, marked with & at the call. These errors enforce that. See Values, mut, and &.

#can't modify parameter NAME: parameters are read-only unless declared mut

A parameter is the caller's value, lent to the function. Changing it would either change the caller's variable behind its back or silently change only a copy, so it is refused. Copy it to a local variable, return the new value, or declare it mut.

Does not compile
fn add_tax(price: float) float:
    price = price * 1.2
    return price

fn main():
    pass

2: error: can't modify parameter `price`: parameters are read-only unless declared `mut`
2: hint: to change only a local copy, copy it first (`price2 = price`) and change `price2`; to change the caller's value, declare `price: mut T` and call with `f(&x)` or `x.f()`

    return price * 1.2

fn add_tax(price: mut float):
    price = price * 1.2

fn main():
    p = 10.0
    print(with_tax(p))
    add_tax(&p)
    print(p)
Output

12.0

#Aliasing

#NAME would see the same value twice: &PLACE can be changed, but PLACE is also passed (argument N)

A function that takes a mut parameter may assume nothing else it can see changes at the same time. Passing the same variable twice breaks that (in transfer(&a, &a, 30) the second write would undo the first). Tern refuses the call. For array elements it can't prove two indices differ, so f(&xs[i], &xs[j]) is refused too.

Does not compile
struct Account:
    balance: int

fn transfer(src: mut Account, dst: mut Account, amount: int):
    src.balance -= amount
    dst.balance += amount

fn main():
    a = Account(100)
    transfer(&a, &a, 30)
Compiler output
10: error: `transfer` would see the same value twice: `&a` can be changed, but `a` is also passed (argument 2)

If you do need the function to read a value while changing it, pass a copy:

fn add_all(xs: mut [int], ys: [int]):
    for y in ys:
        xs.push(y)

fn main():
    xs = [1, 2]
    snapshot = xs
    add_all(&xs, snapshot)
    print(xs)
Output
[1, 2, 1, 2]

#can't read NAME here: a call later in this expression changes it with &NAME, and that call runs first. Read NAME into a variable on the line before

Calls inside an expression run before the plain reads around them: each call's result is computed first. So when one part of an expression reads x and a call further along changes x through &x, the read would see the new value, which isn't what the code says. Tern refuses it instead of picking an order silently (Rust refuses it too).

Does not compile
fn bump(n: mut int) int:
    n += 1
    return n

fn main():
    x = 0
    print(x, bump(&x))
Compiler output
7: error: can't read `x` here: a call later in this expression changes it with `&x`, and that call runs first. Read `x` into a variable on the line before
fn bump(n: mut int) int:
    n += 1
    return n

fn main():
    x = 0
    before = x
    print(before, bump(&x), x)
Output
0 1 1

Reads after the call are fine (bump(&x) + x reads the new x, as written), and so are and / or, which run their right side only after the left.

#runtime error in F (FILE:N): index N out of bounds (length N)

An array or string index is negative or not less than the length. There are no negative indexes: the last element is xs[len(xs) - 1]. This program:

fn main():
    xs = [10, 20, 30]
    print(xs[3])

stops with:

runtime error in main (prog.tn:3): index 3 out of bounds (length 3)

Check the index first, or loop over the array directly. (Slices don't fail: xs[1..10] stops at the end of the array.)

fn main():
    xs = [10, 20, 30]
    i = 3
    if i < len(xs):
        print(xs[i])
    else:
        print("no element", i)
    print(xs[len(xs) - 1], xs[1..10])
Output
no element 3
30 [20, 30]

#runtime error: stack overflow (recursion too deep)

A function recursed so deeply that the thread's stack (64MB) ran out, on the main thread, inside parallel:, or in a task (stack overflow in a task). The program ends with status 2. Recursion a few hundred thousand calls deep is fine; unbounded recursion (a missing base case) is the usual cause. Turn deep recursion over long inputs into a loop.

#runtime error in F (FILE:N): can't convert inf to int

int(x) of a float with no integer value: inf, -inf, nan, or a value outside int's range (can't convert 1e+20 to int (out of range)). Check first with x == x and x < 9_000_000_000_000_000_000.0 and x > -9_000_000_000_000_000_000.0.

#runtime error in F (FILE:N): chr(N): the byte value must be 0 to 255

chr(n) makes a one-byte string, so n must be a byte value.

#runtime error: all tasks are blocked (deadlock)

Every task, main included, waits on a channel, a join, or a shared value with no timeout, so nothing can ever wake them. The message says what main and the other tasks wait for:

runtime error: all tasks are blocked (deadlock): main is waiting for a task to finish; 2 tasks are waiting to receive from a channel

Usually a value is never sent, or two tasks each wait for the other. Waits on sockets, timers (task.sleep, recv_timeout), and task.blocking aren't counted, so a server waiting for connections is never reported.

#runtime error in F (FILE:N): a shared value was used inside its own update

The function passed to s.update(f) called s.get(), s.set(v), or s.update(g) on the same shared value. The update holds the value until f returns, so that would wait forever. Use the value f is given instead.

#task failed: MESSAGE

A task hit a runtime error and nothing joined it (h.join() raises the error again). The error is printed, and when main returns the program exits with status 2. Join the task, or call h.cancel() on it if its failure is expected.
