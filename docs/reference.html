#Tern language reference

This is the complete reference for writing Tern programs. It is written so that a reader who has never seen Tern (a person or an LLM) can write correct code on the first try. Every tern ` block below is a complete program that the test suite (`tern run tests/runner/main.tn -- docs`) compiles and runs; when an `output block follows, the program's output must match it exactly. So the examples here are known to work.

#0. The short version

Tern looks like Python, but it is statically typed and compiled, and every value is a copy: there are no references, pointers, None, classes, or exceptions.

The rules that differ most from Python:

  1. Functions are fn name(a: int, b: str) int:. Every parameter needs a type. The return type comes after the ) with no arrow (-> int is also accepted). No return type = returns nothing.
  2. x = 5 creates a variable. Its type is fixed from then on. x: float = 0.0 states a type. There is no let or var, and there are no global variables. Top-level const NAME = value declares a constant (computed at compile time, or on first use when it calls a function).
  3. The top level of a file may only contain import, from ... import, struct, enum, const, fn, extern, and export fn. The program starts at fn main():.
  4. Types: int (64-bit), float (64-bit), bool, str, [T] (array), {K: V} (map), structs, enums, tuples (int, str), fn(int) str (functions). == compares any of them (except functions) by value. Generics: fn first[T](xs: [T]) T, struct Pair[A, B]. No null: a value that may be missing is an Option[T] (Some(x) or None), a result that may fail a Result[T, E] (§9).
  5. true, false (lowercase). Logic is and, or, not. Strings use double quotes only.
  6. No implicit conversions: 1 + 2.0 is an error. Write float(1) + 2.0 or 1 + int(2.0). str + int is an error: write "n=" + str(n) or f"n={n}".
  7. / on two ints is integer division (truncates toward zero). There is no //.
  8. Parameters are read-only. To let a function change the caller's variable, declare the parameter mut and pass it with &: fn inc(n: mut int) is called as inc(&x).
  9. Assignment copies: after b = a, changing b never changes a (this includes arrays, maps, and structs; the copy is lazy, so it is cheap until one side is written).
  10. for i in 0..n: loops over 0, 1, ..., n-1. There is no range().
  11. Arrays: xs.push(v), xs.pop(), len(xs). push copies v into the array, like = (so v stays usable, and it moves for free when v isn't used again). There is no append, list comprehension, or negative index. Use xs.sorted(), xs.reversed(), sum(xs), xs.sort_by(fn(x) key), xs.map(...), xs.filter(...): each returns a new value and leaves xs alone.
  12. Structs have no methods inside them. Write a function whose first parameter is the struct; then p.area() calls area(p).
  13. Your functions may share a builtin's name (fn get(s: Store, id: int)): a call uses yours when its first parameter fits the first argument, and the builtin otherwise. See §20.

A complete program:

struct Item:
    name: str
    price: float
    qty: int

fn total(items: [Item]) float:
    t = 0.0
    for it in items:
        t += it.price * float(it.qty)
    return t

fn main():
    items: [Item] = []
    items.push(Item("apple", 0.5, 4))
    items.push(Item(name="pear", price=0.75, qty=2))
    print(f"{len(items)} items, total {total(items)}")
    for i, it in items:
        print(i, it.name)
Output
2 items, total 3.5
0 apple
1 pear

#1. Running programs

tern run prog.tn             compile and run (needs clang)
tern run prog.tn -- a b      pass arguments (read them with os.args())
tern check prog.tn           type/safety check only; prints "prog.tn: ok"
tern check --json prog.tn    errors as JSON (for tools and agents)
tern test prog_test.tn       run the `test_*` functions (see the `testing` module, §16)
tern fmt prog.tn             reformat the file in place
tern build prog.tn -o prog   make a native binary
tern emit prog.tn            print the generated C
tern guide                   print this reference
tern guide strings           print only the sections about a topic

check --json prints {"ok": true, "file": ...} or {"ok": false, "errors": [...]}, where each error is {"file", "line", "message", "hint", "source"} (hint is null when there is none; source is the offending line).

Compile errors look like prog.tn:12: error: <message>, often followed by a hint: line when the code looks like another language. All errors in a file are reported at once. A runtime error (index out of bounds, missing map key, division by zero, pop() on an empty array) prints runtime error in f (prog.tn:N): <message> to stderr ((util.tn, line N) when it happened in another file), then the Tern functions it came through (in util.helper <- run <- main), and exits with status 2.

#2. Lexical rules

  • Comments start with # and run to the end of the line. There are no block comments or docstrings.
  • Blocks are made by indentation after a :, like Python. Use 4 spaces. A block with one statement may go on the same line: if x > 0: print(x).
  • A line continues while a (, [, or { is open, or after a trailing \.
  • No semicolons.
  • Integers: 42, 1_000_000, hex 0xff, binary 0b1010, octal 0o17 (_ may separate digits anywhere). A decimal literal must fit in an int (up to 9223372036854775807); a hex, binary, or octal one may use all 64 bits, and above that value it is negative (0xffff_ffff_ffff_ffff is -1), which is handy for hash constants and masks. A literal that doesn't fit is a compile error.
  • Floats: 1.0, 0.5, 1e9, 2.5e-3, 6.02E+23 (an exponent makes a float). A dot needs digits on both sides: not 1. or .5.
  • Strings: "double quotes", on one line. Escapes: \n \t \r \0 \" \\; \xNN is one byte ("\x01", "\xff"); \u00e9 (four hex digits) and \u{1F600} (one to six) are a Unicode character, stored as UTF-8. A malformed \x or \u is a compile error. Any other backslash is kept as is: "a\qb" is the four bytes a \ q b.
  • Multi-line strings: """ ... """ (and f""" ... """) may span lines and take the same escapes; " needs no escape inside. When the text starts on the line after the opening """, that line break and the one before the closing """ are dropped, and the indentation all its lines share is removed, so a block of SQL or HTML can be indented with the code.
  • Raw strings: `C:\dir\file` between backticks: every character as written, no escapes, may span lines (a backtick can't appear inside). Good for regular expressions and JSON.
  • F-strings: f"x = {x}, next = {x + 1}". Any expression whose value is an int, float, bool, or str goes in {} (for an array, map, or struct, use print(label, xs) or json.encode(xs)); {{ and }} are literal braces. No format specs ({x:.2f} is an error): use the fmt module, f"{fmt.fixed(x, 2)}" (§12).
  • Names: letters, digits, _. Names starting with _ are private to their module.
  • Keywords: and break const continue do elif else enum export extern false fn for from if import in mut not null or parallel pass return struct take true while. match is a soft keyword, type is one at the top level (type Name = T), and is is one after an expression (x is None).

#3. Variables and types

fn main():
    n = 10                  # int
    ratio = 0.25            # float
    ok = true               # bool
    name = "tern"           # str
    xs = [1, 2, 3]          # [int]
    ages = {"ada": 36}      # {str: int}
    empty: [str] = []       # an empty collection needs a type...
    later = []              # ...or gets it from its first use
    later.push(1.5)
    n = n + 1               # reassigning keeps the type
    print(n, ratio, ok, name, xs, ages, empty, later)
Output
11 0.25 true tern [1, 2, 3] {"ada": 36} [] [1.5]
  • A variable is created by its first assignment and lives until the end of the block it was created in. Create it before an if if you need it after:
fn main():
    label = ""
    if 3 > 2:
        label = "big"
    else:
        label = "small"
    print(label)
Output
big
  • There is no declaration without a value (x: int alone is an error); use x = 0.
  • Constants go at the top level: const NAME = value or const NAME: type = value. A value made of literals, other such constants, and operators (including a if c else b) is an int, float, str, or bool computed when compiling; it can also be a match pattern. A constant can be used anywhere a value can, and from other modules (config.PORT, from config import PORT). There are no global variables: constants can't change, so every task can read them.
  • Any other value (a function call, an array, a struct, a compiled regex, a task.shared_map() cache) is computed when the program first uses it, once, even if many tasks use it at the same moment, and kept: const EMAIL = re.must("[^@ ]+@[^@ ]+") compiles the pattern once for the whole program. Its type comes from the value (write it, const X: [str] = [], when it can't). It can't be a match pattern, and a value that needs itself is a runtime error.
const MAX_USERS = 100
const NAME = "tern"
const BANNER = NAME + " v2"
const MASK: int = (1 << 12) - 1
const LIMIT = MAX_USERS * 2 if MASK > 0 else 0

fn kind(n: int) str:
    match n:
        MAX_USERS:
            return "full"
        _:
            return "ok"

fn main():
    print(BANNER, LIMIT, MASK, kind(100), kind(7))
Output
tern v2 200 4095 full ok
import re
import task

const WORD = re.must("[a-z]+")
const STOP = ["the", "a", "of"]
const SEEN = task.shared_map()            # one cache for the whole program

fn words(s: str) int:
    n = 0
    for m in WORD.find_all(s):
        if not (m.text in STOP):
            SEEN.add_int(m.text, 1)
            n += 1
    return n

fn main():
    lines = ["the cat sat", "a cat of note"]
    parallel for i in 0..len(lines):
        words(lines[i])
    print(SEEN.get_int("cat"), SEEN.get_int("the"), len(STOP))
Output
2 0 3
  • Types can't change: x = 1 then x = "a" is an error.
  • Type syntax: int float bool str byte f32, bytes16 and f32x4 (16 bytes / four f32s at once: std simd), [int], [[str]], {str: int}, {int: [Point]}, (int, str), Point, http.Request (a type from a module), fn(int, str) bool, fn(str) (returns nothing), ptr (C pointer).
  • Wrong type names from other languages are errors: string, i32, i64, f64, list[int], List<int>, dict, Vec<T>. (void is accepted only as a return type, where it means the same as leaving the return type out.)
  • Default values when you need one: 0, 0.0, false, "", [], {}.

#5. Control flow

fn main():
    for i in 0..3:                  # 0, 1, 2 (end is exclusive; no step)
        print("i", i)
    xs = ["a", "b"]
    for x in xs:                    # elements
        print(x)
    for i, x in xs:                 # index and element
        print(i, x)
    m = {"one": 1, "two": 2}
    for k, v in m:                  # key and value, in insertion order
        print(k, v)
    n = 3
    while n > 0:                    # counting down: use while
        n -= 1
        if n == 1:
            continue
        print("n", n)
    x = 7
    if x < 5:
        print("small")
    elif x < 10:                    # `elif`, never `else if`
        print("medium")
    else:
        print("large")
    for i in 0..100:
        if i == 2:
            break
    if x > 0:
        pass                        # an empty block needs `pass`
Output
i 0
i 1
i 2
a
b
0 a
1 b
one 1
two 2
n 2
n 0
medium
  • for i in a..b with a >= b runs zero times. To count down, use while.
  • The loop variable can't be assigned, and the array or map being looped over can't be changed inside the loop. To change elements while looping, loop over indices: for i in 0..len(xs): xs[i] = xs[i] * 2.
  • match is covered in §9. There is no switch, try, with, goto, or do/while.

#6. Functions

fn add(a: int, b: int) int:
    return a + b

fn greet(name: str):                        # no return type: returns nothing
    print("hello " + name)

fn divmod(a: int, b: int, q: mut int, r: mut int):
    q = a / b                               # `mut` parameters write back to the caller
    r = a % b

fn main():
    greet("ada")
    q = 0
    r = 0
    divmod(17, 5, &q, &r)                   # `&` marks each argument that may change
    print(add(2, 3), q, r)
Output
hello ada
5 3 2
  • Every parameter has a type. There are no default values, keyword arguments (named arguments are only for building structs), variadic parameters, or overloading.
  • A function with a return type must end with a return on every path.
  • Parameter modes: - default: read-only. Assigning to it, or calling push on it, is an error. - mut: the function may change it and the caller sees the change. The caller must write &x. - take: the value moves into the function (no copy). The caller can't use x afterwards (pass copy(x) to keep a copy).
  • To return several values, return a tuple: fn divmod(a: int, b: int) (int, int): then return q, r, and the caller writes q, r = divmod(7, 2) (§7, Tuples).
  • To report failure, return a Result[T, E] (Ok(value) or Err(error)), or an Option[T] when there's nothing to say about why (§9). There are no exceptions.
  • Method syntax: x.f(a, b) is the same call as f(x, a, b). If the first parameter is mut, write x.f(...) or f(&x, ...). x.f also finds f in the module where x's type is defined, so d.exec(...) calls sqlite.exec(d, ...).
  • Functions can be defined inside functions (they are closures, §13) and may recurse. Top-level functions may be called before they are defined.

#7. Structs

struct Point:
    x, y: int                              # several fields of one type

struct Player:
    name: str
    pos: Point
    scores: [int]

fn dist(p: Point) int:                     # "methods" are plain functions
    return abs(p.x) + abs(p.y)

fn move(p: mut Player, dx: int):          # a "mutating method"
    p.pos.x += dx

fn main():
    a = Point(1, 2)                        # positional: fields in order
    b = Point(y=5, x=-3)                   # named: any order; every field is required
    pl = Player("zed", a, [])
    pl.scores.push(10)                     # nested fields and arrays change in place
    pl.move(4)                             # same as move(&pl, 4)
    c = a                                  # a copy
    c.x = 100
    print(a.x, c.x, b.dist(), pl)
Output
1 100 8 Player{name: "zed", pos: Point{x: 5, y: 2}, scores: [10]}
  • All fields must be given when building a struct; there are no default field values. Write a constructor function if you want defaults: fn new_player(name: str) Player:.
  • No self, no classes, no inheritance, no interfaces. == compares two structs field by field; when equality means something else, write fn same_user(a: User, b: User) bool.
  • A struct may contain an array of itself (kids: [Node]) but not itself directly. For graphs, store nodes in an array and refer to them by index.
  • print shows structs as Name{field: value, ...}.

#Tuples

A tuple is a fixed group of values of any types, written (a, b); its type is written the same way, (int, str). It is a value like a struct whose fields have no names: read them by position with t.0, t.1. Functions return several values as a tuple, and a, b = ... unpacks one (each name on the left is a new variable, an existing one, a field or element, or _ to skip a value).

fn divmod(a: int, b: int) (int, int):
    return a / b, a % b                   # parentheses are optional after `return` and `=`

fn main():
    q, r = divmod(17, 5)
    print(q, r)
    t = divmod(9, 2)
    print(t, t.0, t.1)
    a = 1
    b = 2
    a, b = b, a                           # swap
    _, rest = divmod(7, 3)
    scores: [(str, int)] = [("ada", 3), ("bob", 5)]
    scores.push(("cy", 4))
    for s in scores:
        print(s.0, s.1)
    print(a, b, rest, scores[1])
Output
3 2
(4, 1) 4 1
ada 3
bob 5
cy 4
2 1 1 ("bob", 5)
  • A tuple has two or more values; there is no one-value tuple. t.0 = 5 changes one value.
  • The number of names on the left of a, b = ... must match the tuple.
  • Tuples can go anywhere a type can: in arrays, maps, struct fields, and function types.
  • print shows (1, "a"), and == compares tuples value by value. Tuples can't be turned into JSON yet.

#Generics

Functions, structs, and enums can take type parameters in [ ] after their name. A use with concrete types makes a version of the function or type for those types (like C++ templates or Rust): it runs exactly as fast as code written by hand for them.

struct Pair[A, B]:
    left: A
    right: B

enum Tree[T]:                             # recursive generic enums work too
    Leaf
    Node(l: Tree[T], v: T, r: Tree[T])

fn first[T](xs: [T]) T:
    return xs[0]

fn largest[T: Ord](xs: [T]) T:            # a constraint: T must support < and >
    best = xs[0]
    for x in xs:
        if x > best:
            best = x
    return best

fn map_all[A, B](xs: [A], f: fn(A) B) [B]:
    out: [B] = []
    for x in xs:
        out.push(f(x))
    return out

fn insert[T: Ord](t: Tree[T], v: T) Tree[T]:
    match t:
        Leaf:
            return Tree.Node(Tree[T].Leaf, v, Tree[T].Leaf)
        Node(l, x, r):
            if v < x:
                return Tree.Node(insert(l, v), x, r)
            return Tree.Node(l, x, insert(r, v))

fn main():
    print(first([3, 1]), first(["a"]), largest([2.5, 9.0]))
    p = Pair(1, "one")                    # Pair[int, str], from the values
    q: Pair[str, [int]] = Pair("n", [])   # the declared type fills in [int]
    print(p, q, map_all([1, 2], fn(x) x * 10), first[str](["z"]))
    t = Tree[int].Leaf                    # explicit type arguments
    for v in [5, 2, 8]:
        t = insert(t, v)
    print(t)
Output
3 a 9.0
Pair{left: 1, right: "one"} Pair{left: "n", right: []} [10, 20] z
Tree.Node(l: Tree.Node(l: Tree.Leaf, v: 2, r: Tree.Leaf), v: 5, r: Tree.Node(l: Tree.Leaf, v: 8, r: Tree.Leaf))
  • Type arguments are usually inferred: from the arguments, then from the type the result is going into (a typed variable, a return, a parameter), then from lambdas. When they can't be, write them: first[int](xs), Pair[int, str](1, "a"), Tree[int].Leaf.
  • A generic type always needs its arguments where a type is written: Pair[int, str], not Pair.
  • Constraints: T: Ord (int, float, str: <, >, sorting), T: Eq (==), T: Hash (usable as a map key); several: T: Ord + Hash. Without a constraint any type is accepted, and the body is checked for each type it is used with; an error there names the version, e.g. (in `total[Point]`, used on line 12).
  • A generic function used as a value needs its arguments: f = first[int].
  • There are no traits or interfaces: pass behavior as a function value (fn(T, T) bool).

#Type aliases

type Name = T at the top level of a module gives a type a second name. The alias is the type: values pass freely between the two names, Name(...) constructs one, and x.f() finds f in the module that defines the original. A package uses aliases to present types that live elsewhere under its own name (roost.Request is http.Request).

struct Point:
    x: int
    y: int

type Pos = Point
type Path = [Pos]
type Scores = {str: int}

fn walk(p: Path) int:
    total = 0
    for q in p:
        total += abs(q.x) + abs(q.y)
    return total

fn main():
    a = Pos(3, -4)
    b: Point = a                       # the same type under two names
    s: Scores = {"ada": walk([a, b])}
    print(a, s)
Output
Point{x: 3, y: -4} {"ada": 14}
  • The alias's target is resolved in the alias's own module, so type Request = http.Request needs import http there; users of the alias don't.
  • An alias can name any type ([T], {K: V}, fn(int) str, another alias), but not itself, directly or through other aliases.
  • Errors and printed values use the original name (Point above).
  • type is a soft keyword: only type NAME = at the top level declares an alias, so type still works as a field or variable name.

#8. Arrays [T]

fn main():
    xs = [3, 1, 2]
    xs.push(5)                     # append at the end
    last = xs.pop()                # remove and return the last element
    print(xs, last, len(xs), xs[0])
    xs[0] = 30
    zeros = [0] * 4                # [value] * n
    grid = [[0] * 3] * 2           # 2 rows of 3 (each row is its own copy)
    grid[1][2] = 7
    print(zeros, grid)
    print(xs[1..], xs[..2], xs[1..2], 2 in xs)   # slices are copies
    ys = xs.sort_by(fn(x) x)       # returns a new sorted array (stable)
    down = xs.sort_by(fn(x) -x)    # descending: negate a number key
    evens = [1, 2, 3, 4].filter(fn(x) x % 2 == 0)
    squares = [1, 2, 3].map(fn(x) x * x)
    print(ys, down, evens, squares, xs)

#Bytes

byte is a number from 0 to 255, for binary data: pixels, network buffers, hashes. A [byte] stores one byte per element (an [int] uses eight), so a 1024x1024 RGBA image is 4MB.

fn main():
    px: [byte] = [255, 128, 0, 64]      # a number 0-255 is a byte where one is expected
    gray = (px[0] * 77 + px[1] * 150 + px[2] * 29) >> 8    # bytes in arithmetic are ints
    out = [byte(0)] * 3
    out[0] = byte(gray)                 # storing an int takes byte(n): its low 8 bits
    out[1] = byte(300)
    out[2] = 250
    out[2] += 10                        # op= on a byte wraps
    data = "Tern".to_bytes()            # str <-> [byte] share memory: no copy
    data[0] = 116
    print(gray, out, data.to_str(), int(px[1]) * 2)

151 [151, 44, 4] tern 256
  • In arithmetic and comparisons a byte counts as an int, and so does the result: px[0] * 77 can't overflow. -b is an int too.
  • Storing an int into a byte (a variable, element, field, or argument) takes byte(n), which keeps the low 8 bits. A literal from 0 to 255 needs no conversion; one outside that range is an error. b += n (any op=) on a byte wraps, as byte(b + n) would.
  • int(b) and float(b) convert back. s.byte(i) still returns an int.
  • s.to_bytes() gives a string's bytes, bs.to_str() makes a string of them. Both share the block (a str and a [byte] are laid out the same); writing to either copies it first.
  • print and json.encode show bytes as numbers; json.decode rejects numbers outside 0-255.

#32-bit floats

f32 is a 32-bit float, for big arrays of numbers: vectors, embeddings, audio, model weights. An [f32] stores 4 bytes per element (a [float] uses eight), so a million 768-number embeddings take 3GB instead of 6GB. std simd works on four of them at once (f32x4), and std binary reads and writes them as raw bytes (binary.f32s_le, binary.f16s_le).

#Option and Result

Two generic enums are always available, without an import:

enum Option[T]:            enum Result[T, E]:
    Some(value: T)             Ok(value: T)
    None                       Err(error: E)

Option[T] is a value that may be missing (Tern has no null); Result[T, E] is a result or an error (Tern has no exceptions). Build them bare: Some(3), None, Ok(v), Err("bad"). Test them with match, or with x is Pattern, whose names are bound in the if or while block. And x? gives the value inside Some / Ok, or else returns the None / Err from the function at once (the function must return an Option, or a Result with the same error type).

struct User:
    name: str
    age: int

fn find_user(us: [User], name: str) Option[User]:
    for u in us:
        if u.name == name:
            return Some(u)
    return None

fn parse_age(s: str) Result[int, str]:
    n = s.to_int(-1)
    if n < 0:
        return Err(f"bad age: {s}")
    return Ok(n)

fn total_age(texts: [str]) Result[int, str]:
    t = 0
    for s in texts:
        t += parse_age(s)?                  # an Err returns from total_age right here
    return Ok(t)

    cur: Option[int] = Some(3)

  • x is V(a, b) binds a and b only as the condition of an if / while, or on the left of and there (if o is Some(v) and v > 0:). Anywhere else it's a plain test: x is None, r is Ok(_). There's no is not: write not (x is None).

Tern has no references, so aliasing bugs and data races are compile errors. The rules and the fix for each:

#15. Parallelism

fn fib(n: int) int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

fn main():

        a = fib(20)
        b = fib(21)

            c = fib(5)
            c += 1
    print(a, b, c)
    xs = [0] * 8
    parallel for i in 0..len(xs):     # iterations run across all cores

    for x in xs:
        total += x

  • The compiler rejects any task that writes a variable another task reads or writes. One exception: tasks may write different elements of an array written with literal indexes (xs[0] = a() in one task, xs[1] = b() in another), if they don't touch the array otherwise.

Tasks (import task) are green threads, like Go's goroutines: code in a task looks blocking, but only the task waits (ch.recv(), h.join(), time.sleep, socket reads), and its core runs other tasks meanwhile. Copying a chan, task, or shared value shares it. Values sent through a channel are copied (cheaply: copy-on-write).

fn main():

        n += 1

  • A channel needs its type written: ch: chan[int] = task.channel(8). ch.recv() on a closed, empty channel is a runtime error; for x in ch: and ch.next(&x) stop instead.

The program ends when main returns; if a task failed and nobody joined it, its error is printed and the program exits with status 2 (tasks spawned inside web handlers don't count). h.cancel() on a task that already failed discards its error.

  • os.on_error(f) calls f(os.ErrorReport) for every runtime error from then on, caught ones too (a failed task, a web handler's 500): for error trackers. See os.
  • Code inside parallel: may use channels too; there it waits like a thread.

#Groups of tasks: task.all, task.try_all (Go's errgroup)

task.all(fs) runs every function in fs ([fn() T]) at once and returns their results in order; a runtime error in one is raised in the caller. task.try_all(fs) does the same for functions that return Result[T, E]: Ok with every value in order, or the first Err to arrive, after cancelling the tasks still running. task.try_all_limit(fs, n) runs at most n at a time (Go's SetLimit), for "fetch these 500 URLs, 8 at once".

import task

fn fetch(id: int) Result[str, str]:
    if id == 13:
        return Err(f"page {id}: not found")
    return Ok(f"page {id}")

fn main():
    print(task.all([fn() 2 + 2, fn() 3 * 3]))
    good: [fn() Result[str, str]] = []
    for id in 0..4:
        good.push(fn() fetch(id))
    print(task.try_all_limit(good, 2))
    bad: [fn() Result[str, str]] = [fn() fetch(1), fn() fetch(13)]
    print(task.try_all(bad))                  # the first Err; any still running are cancelled
Output
[4, 9]
Ok(["page 0", "page 1", "page 2", "page 3"])
Err("page 13: not found")

#Counters and caches: task.atomic, task.shared_map

shared[T] changes any value safely, but each get and update takes a lock that tasks wait for in turn: fine for occasional changes, slow for a counter or cache that every request touches. For those two cases there are faster handles (copies share one, like channels):

  • task.atomic(v): an int changed with atomic instructions. a.load(), a.store(v), a.add(n) (returns the new value), a.cas(old, new) (stores new if the value was old).
  • task.shared_map(): a str -> str map any task can use at once (m.put(k, v), m.get_or(k, default), m.has(k), m.remove(k), m.count()), plus an int per key for counting (m.add_int(k, n), m.get_int(k)).

Under contention they are hundreds of times faster than shared[T]. Copies share the same one (like a channel), and the last copy gone frees it, entries and all: a cache can start again with a fresh map.

import task

fn visit(hits: task.Atomic, pages: task.SharedMap, path: str) int:
    pages.add_int(path, 1)
    return hits.add(1)

fn main():
    hits = task.atomic(0)
    pages = task.shared_map()
    pages.put("/", "home")
    hs: [task[int]] = []
    for i in 0..100:
        p = "/" if i % 2 == 0 else "/about"
        hs.push(task.spawn(fn() visit(hits, pages, p)))
    for h in hs:
        h.join()
    print(hits.load(), pages.get_int("/"), pages.get_int("/about"), pages.get_or("/", "?"))
Output
100 50 50 home

A web server with a database (build with tern build app.tn -o app):

import http
import sqlite
import json

struct Todo:
    id: int
    title: str

fn handle(req: http.Request, d: sqlite.Db) http.Response:
    params: {str: str} = {}
    if req.method == "GET" and req.path == "/todos":
        todos: [Todo] = []
        d.query_into("SELECT id, title FROM todos", [], &todos)
        return http.json(json.encode(todos))
    if req.method == "POST" and http.match(req.path, "/todos/{title}", &params):
        id = d.exec("INSERT INTO todos (title) VALUES (?)", [params["title"]])
        return http.json(json.encode(Todo(id, params["title"])))
    return http.not_found()

fn main():
    d = sqlite.open("todos.db")
    d.exec("CREATE TABLE IF NOT EXISTS todos (id INTEGER PRIMARY KEY, title TEXT)", [])
    http.serve(8080, handle, d)
  • The handler is fn(req: http.Request) http.Response, or takes a second parameter app (shared read-only by all threads), or app: mut App with http.serve(port, handle, &app) (requests that change it run one at a time).
  • A runtime error inside a handler becomes a 500 response; the server keeps running.
  • SQL parameters are always strings ([str(id)]) and are bound safely.
  • Each server thread opens its own connection, so sqlite.open(":memory:") gives every thread a separate, empty database. Servers need a file path.
  • A sqlite.Db is a handle, so a read-only d: sqlite.Db parameter can still run INSERTs: the database is outside the program's values. "Read-only" is about Tern values only.

#17. Modules and packages

Every .tn file is a module. import models looks in the standard library and the first-party packages (roost, queue, pg), then for models.tn or models/ (a directory of .tn files forming one package) next to the main file, then in deps/. Use models.User, models.load(...), or from models import User, load. Names starting with _ are private. Third-party packages are git repositories: list them in a tern.mod file next to your program and run tern get, which vendors them into deps/, where import finds them (see cli.md).

#18. Other targets and C

  • --target wasm | ios | ios-sim | android; build --lib makes a C library with a header from export fn functions; --shared makes a .so/.dylib. On wasm, --lib also writes a JavaScript loader. Wasm runs parallel sequentially; sqlite and http aren't available there.
  • Calling C: an extern "header.h": block of fn signatures (see README.md, "Calling C"). Only int float bool str ptr [int] [float] and functions of those cross the boundary. ptr is an opaque C pointer; null is the null pointer (p: ptr = null) and p.is_null() tests for it. null is only a ptr: other types have no null. A str result stops at the first NUL byte; for binary data, return a ptr and a length and copy it with string_at(p, n) str (see guides/c-interop.md).

A function of your own, in the program or in a module, may have one of these names. A call get(a, ...) or a.get(...) goes to your get when its first parameter fits a and the number of arguments matches; otherwise it goes to the builtin, so the builtin still works on strings, arrays, and maps next to yours:

struct Store:
    names: [str]

fn get(s: Store, i: int) str:
    return s.names[i]

fn len(s: Store) int:
    return len(s.names)

fn main():
    st = Store(["ada", "bob"])
    ages = {"ada": 36}
    print(st.get(1), get(st, 0), len(st), ages.get("ada", 0), len("hey"))
Output
bob ada 2 36 3

When the first argument is itself of a builtin type (a string, number, array, or map), a call that doesn't fit your function goes to the builtin; for any other type, the error is about your function. Functions in an extern block and export fn functions can't take a builtin's name, because C sees that name: rename an extern one with = "c_name".

#21. Idioms

struct Parsed:
    ok: bool
    value: int

fn parse_port(s: str) Parsed:          # failure without exceptions
    n = s.to_int(-1)
    if n < 1 or n > 65535:
        return Parsed(false, 0)
    return Parsed(true, n)

fn index_of(xs: [str], want: str) int:  # search
    for i, x in xs:
        if x == want:
            return i
    return -1

fn main():
    p = parse_port("8080")
    if p.ok:
        print("port", p.value)

Graphs and trees that need links between nodes use indexes into an array:

struct Node:
    name: str
    edges: [int]                          # indexes into the nodes array

fn main():
    nodes = [Node("a", [1, 2]), Node("b", [2]), Node("c", [])]
    seen = [false] * len(nodes)
    todo = [0]
    order: [str] = []
    while len(todo) > 0:
        n = todo.pop()
        if seen[n]:
            continue
        seen[n] = true
        order.push(nodes[n].name)
        for e in nodes[n].edges:
            todo.push(e)
    print(order)
